## Що зроблено

Дві вкладки-заготовки веб-панелі, група навігації «Проєкти» (між «Фінансами» і «Налаштуваннями»):

| Шлях | Сторінка | Навігація |
|------|----------|-----------|
| `/sushi` | `artifacts/web/src/pages/Sushi.tsx` | «Суші», іконка Fish |
| `/andros` | `artifacts/web/src/pages/Andros.tsx` | «Андрос», іконка Citrus |

Зачеплені файли:
- `artifacts/web/src/App.tsx` — роути з `guard(...)`;
- `artifacts/web/src/components/Layout.tsx` — група «Проєкти» в NAV;
- `artifacts/web/src/lib/roles.ts` + `artifacts/api-server/src/lib/roles.ts` — ключі `/sushi`, `/andros` у каталозі сторінок (два файли — дзеркала, тримати синхронними);
- `artifacts/web/src/lib/i18n.tsx` — EN-переклади назв і текстів заготовок.

**Доступ:** поки бачить лише owner. Видати іншим ролям — Адміни → Ролі (ключі вже в каталозі), без коду і без SQL. Бекенд-роутів і таблиць БД ще немає.

## Як переносити функціонал (правила репо, які легко зачепити)

1. **Веб:** наповнюй `Sushi.tsx` / `Andros.tsx`; якщо сторінка розростається — дроби на компоненти в `pages/sushi/`, `pages/andros/`. Стиль — як сусідні сторінки (`Card`/`PageHeader`/`ui.tsx`, TanStack Query через обгортки `get/post/patch/del` з `lib/api.ts`).
2. **Fetch до `/api` — лише через `api()`/`upload()`** з `web/src/lib/api.ts`: мутації без заголовка `X-Requested-With: grafik` ловлять `403 {"error":"csrf"}`.
3. **Бекенд:** нові роутери — `routes/sushi.ts` / `routes/andros.ts`, монтування в `routes/index.ts`. Авторизаційний гейт — **скоуплений по префіксу** (`router.use("/sushi", requireCap(...))`), не голий `router.use(...)` — інакше зачепиш роутери, змонтовані нижче (латентний баг, уже ловили).
4. **Схема БД** — лише в `lib/db/src/schema/workers.ts` + ручний SQL-файл у `deploy/migrations/` (drizzle-kit push не використовуємо). Після зміни схеми — `pnpm run typecheck:libs`.
5. **i18n:** веб — «укр-рядок-як-ключ», кожен новий текст обгортай `t()` і додавай EN-пару в `lib/i18n.tsx` (секція `/sushi + /andros` уже є, маркер `@i18n-append`).
6. **Tailwind v4** — лише буквальні класи (динамічні рядки сканер не бачить); темна тема — стандартні шкали (`bg-white`, `slate-*`), без hex-хардкодів.
7. **Перевірка перед PR:** `pnpm run typecheck` + `pnpm --filter @workspace/web run build`; якщо чіпав бекенд — ще `run test` і `run build` api-server.
8. **Паралельна робота:** вкладки ізольовані у своїх файлах саме щоб PR-и не конфліктували з основною розробкою; спільні файли (`App.tsx`, `Layout.tsx`, `roles.ts`, `i18n.tsx`, `routes/index.ts`) чіпай точково і ребейзься перед мержем.
