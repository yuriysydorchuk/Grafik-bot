## Що зроблено

1. **Сповіщення про зміну диспозиційності** (`bot/index.ts` `saveAvailability`):
   кожен догруз доступності після першого подання (або перше подання, коли тиждень
   уже «в роботі» для фабрики працівника) → `notifyRoles("scheduler", type:
   "availability_change")` — Telegram графіковим/owner + дзвіночок на сайті
   (клік веде на /availability). Перше «нормальне» подання — тихе.
2. **Сторінка Доступність** (`GET /availability` + `Availability.tsx`):
   колонка «Заповнено» (час останнього Telegram-подання), клік — модалка історії
   батчів (батч = рядки з однаковим `submitted_at`; «Перше заповнення» / «Додав(ла)
   пізніше»); «пізні» батчі (після `factoryWeekReleaseAt`) — рожеві + бейдж
   «📝 після затвердж.» на рядку. Все derived з наявних таблиць, БЕЗ нової схеми;
   історія віддається лише для тижнів свіжіших за 14 днів (вимога власника
   «зберігати 2 тижні» — просто не показуємо старе, чистити нічого).
3. **«Мій графік» працівника** (`bot/views.ts` `showWorkerSchedule` + `showMyScheduleWeek`):
   поденні стани замість фальшивого «вихідний»: зміна (розісланий запис) /
   «вихідний» (день фабрики released або порожній день released-тижня) /
   «⏳ ще не затверджено» (є нерозіслані записи чи тиждень не запущений).
   Таби «Цей/Наступний тиждень» — завжди. Нові i18n-ключі `sched.pending`,
   `sched.notApprovedWeek` (5 мов); `sched.noApproved` видалений.
   **Ключова семантика:** «затвердити день» у веб-графіку = РОЗСИЛКА
   (`POST /schedule/notify` з day, слід — `sent_at`), статусу дня не існує.
4. **Бот-затвердження тижня** тепер пише рядки `schedule_approvals` по фабриках
   з записами — дзеркально до веб `POST /schedule/approve` (раніше лише статус тижня).
5. **`services/weeks.ts` → `factoryWeekReleaseAt(weekStart, factoryId)`** — спільний
   резолвер «коли тиждень став у роботі для фабрики»: min(затвердження фабрики,
   перший `sent_at`); `factoryId=null` → фолбек на статус тижня.
6. **esbuild `keepNames: true`** (`artifacts/api-server/build.mjs`): без нього
   перейменований при колізії клас поліфіла (`AbortSignal2`) валив полінг бота —
   node-fetch перевіряє `constructor.name === "AbortSignal"`. Проявилось у свіжому
   локальному бандлі (нові deps фінбатчу), профілактично поїхало і на прод.
7. **Тести**: `bot/worker-schedule-view.integration.test.ts` (3 сценарії: draft-тиждень
   без «вихідних», поденний мікс, пінг про пізній догруз); у test/harness.ts додані
   `schedule_approvals`+`notifications` (import/export/TRUNCATE).
