## Що сталося

Працівники поскаржилися: «не могли заповнити графік, писало що сервіс недоступний в боті».

Розбір показав:

- **Флоу доступності був справний увесь час** — записи в `availability` йшли безперервно (на тиждень 10.08 заповнили 106 осіб ще до фіксу); жодних падінь процесу (усі pm2-рестарти graceful = деплої), 409 немає, збою Telegram 06.08 не було.
- **Реальний баг:** «🏭 Інфо фабрики» для BIMIZ/ALMIZ мовчки падало з 01.08 (≥14 разів): у назвах зупинок вшиті goo.gl-лінки з `_` (`?g_st=ic`) → `400 can't parse entities` → тиша для працівника.
- **Чому «тиша», а не plain-text fallback:** обгортка `callApi` в `bot/instance.ts` патчила лише інстанс `bot.telegram`, а Telegraf у `handleUpdate` створює **новий** `Telegram`-інстанс на кожен update → усі `ctx.reply` були поза fallback-ом.
- Видима працівникам «недоступність» 06.08, найімовірніше, наклалась на серію швидких деплой-рестартів 14:19–14:53 (3 шт., паралельна сесія деплоїла фінблок).

## Що зроблено (коміт `f304df9`, на проді з 06.08 ~15:40)

- `bot/display.ts`: **`mdSafeWithLinks(text, label)`** — URL-и з вільного тексту стають `[label](url)` (`)` у URL → `%29`), решта тексту через `mdSafe`. Юніт-тести `bot/display.test.ts` (вкл. точний кейс BIMIZ).
- `bot/index.ts` (інфо фабрики): зупинки через `mdSafeWithLinks(..., t(lang,"fac.map"))`; назва/адреса фабрики через `mdSafe`. Рядок тепер: `• Заправка / Fuel station BP [📍 Мапа](…) — бути о *20:40*`.
- `bot/i18n.ts`: ключ `fac.map` (uk/en/es/ru/pl).
- `bot/instance.ts`: fallback перенесено на `Telegram.prototype.callApi` — покриває і `ctx.reply`/`editMessageText`.
- Деплой за скілом `/deploy`: бекап → pull → build.sh → healthz `{"status":"ok","db":"ok","bot":"up"}`, логи чисті.
