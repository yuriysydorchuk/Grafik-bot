# API routes — повний довідник

Детальний опис усіх REST-маршрутів (`/api`) з поведінкою, гейтами й датованими рішеннями. Винесено з `PROJECT_MAP.md` (28.08.2026) — там лишився компактний індекс груп. **Читати цільово** (grep по маршруту/ключовому слову) — файл великий, цілком не читається.

Змінюєш/додаєш API — онови відповідний блок тут (як раніше в PROJECT_MAP).

## API routes

Префікс `/api`. Авторизація: сесійний cookie `grafik_session` (`authRequired`, HMAC-токен зі вшитим `token_version`); мутації під `requireRole(...)`; керування адмінами — `requireMainAdmin`. Фінанси — owner only. **Відкликання сесій:** `authRequired` звіряє `payload.tv` з `admins.token_version` щозапиту; logout / зміна пароля / reset-web інкрементять версію → всі старі токени адміна миттєво недійсні («вийти скрізь»). 2FA-код — `crypto.randomInt`.

**Auth:** `POST /auth/login`, `POST /auth/verify-2fa`, `POST /auth/telegram-webapp` (вхід із Telegram Mini App: верифікація WebApp `initData` HMAC-ом бот-токена — `lib/telegramWebApp.ts`, під тестами; сесія видається адміну з відповідним `telegram_id`), `POST /auth/web-lang` (мова панелі → `admins.web_lang`; `/auth/me` віддає `lang` з фолбеком на мову водія з бота — localStorage у вебвʼю Mini App не живе), `POST /auth/web-prefs` (персональні UI-налаштування панелі key→value → `admins.web_prefs` jsonb: порядок вкладок міст/фабрик в Обліку годин і Сводних + порядок колонок таблиць drag-ом за заголовок (`order.hours.cols`, `order.svodni.cols{,Sens}.{місто}`) і видимість колонок Обліку годин (`hidden.hours.cols`) — суто відображення, суми/експорти не залежать; `/auth/me` віддає `prefs`; веб-хелпери — `web/src/lib/prefs.ts`), `POST /auth/logout`, `GET /auth/me` · **Health:** `GET /healthz`

**Працівники/документи:** `GET/POST /workers` (список віддає всім ролям `legalStatus` нормалізований + похідні `student`/`stud26` — канон `stud26Of`, вік з `birth_date`; на /workers фільтри легалізація/національність/студ-до-26 і підсвітка: rose = oczekuje «не зголошений», amber = без форми і не студент «не оформлений», yellow = студент без форми; колонка «Легалізація» з бейджами `LEGAL_BADGE`), `GET/PATCH /workers/:id`, `POST /workers/:id/fire|restore` (fire приймає опційну `date` «від коли» — множинне звільнення з обліку годин; дані після дати не видаляються, сводна позначає період «не оформлений»), `DELETE /workers/:id` (hard-delete, owner), `GET /workers/:id/invite`, `GET/POST /workers/:id/documents`, `PATCH/DELETE /worker-documents/:id`, `POST/GET /worker-documents/:id/file` (аплоуд/стрім файлу, диск `uploads/`), `GET/POST/PATCH/DELETE /document-types`

**Довідники:** `GET/POST/PATCH/DELETE /companies`, `GET/POST/PATCH/DELETE /positions`, `GET/POST/PATCH /factories` (+ `minDaysPerWeek` — мінімум днів доступності на тиждень, бот не приймає менше; `emailRecipients` у відповіді), `PUT /factories/:id/email-recipients` (повна заміна списку отримувачів графіку `[{email,name?,templateId?}]`; `factories.client_email` — кеш «усі через кому» для старих читачів), `GET /factories/:id/join-link`

**Водії:** `GET/POST/PATCH/DELETE /drivers` (мутації — `editData` АБО `assignDrivers`: головний водій керує списком і з сайту), `GET /drivers/:id/invite`, `GET /driver-board`, `GET /driver-days/:id`, `GET /mileage` (пробіг по змінах водіїв, з номером авто), `PATCH /driver-workdays/:id` (виправлення пробігу; `editData` АБО `assignDrivers`), `GET/POST/PATCH/DELETE /vehicles` (автопарк; ті самі гейти; видалення м'яке — старі зміни тримають номер у звіті)

**Замовлення/доступність:** `GET/PUT /orders`, `GET /availability` (рядок працівника несе `filledAt` — останнє Telegram-подання, `history` — батчі подань за `submitted_at` з маркером `late` = після затвердження/розсилки тижня фабрики (`factoryWeekReleaseAt` у `services/weeks.ts`), `hasLate` — бейдж «📝 після затвердж.»; історія віддається лише для тижнів свіжіших 14 днів — derived, без окремої таблиці), `GET /availability/missing`, `POST /availability/remind`. Догруз диспозиційності в боті після першого подання (чи коли тиждень уже в роботі) шле `notifyRoles("scheduler", "availability_change")` — Telegram + дзвіночок (клік → /availability)

**Графік:** `GET /weeks`, `GET /schedule` (віддає і `shiftOverrides` — разові зміни тижня), `GET /schedule/excel`, `POST /schedule/generate` (`augment: true` = «доповнити»: наявні записи не видаляються, заповнюються лише порожні клітинки), `POST /schedule/approve`, `POST/DELETE /schedule/shift-override` (разова зміна на конкретну дату фабрики: № зміни + start/end; правлять `hoursOverride` явок клітинки), `POST /schedule/email` (лист клієнту фабрики: тиждень або день, з Excel-вкладенням), `GET /email-templates` + `POST /email-templates`, `PUT/DELETE /email-templates/:id`, `POST /email-templates/:id/default` (глобальний список шаблонів у `email_templates`; кожен отримувач фабрики може мати свій, `isDefault` — для решти; старі `settings.email_tpl_schedule_*` мігрують у перший шаблон при першому зверненні), `POST /schedule/entry` (створює draft-тиждень, якщо графік ще не генерувався — ручне збирання drag-ом працює до «Згенерувати»; друга зміна того ж дня на тій самій фабриці дозволена — відповідь несе `restGapHours`, якщо пауза між змінами < 5 год (`services/restGap.ts`), веб підсвічує помаранчевим; дубль зміни / інша фабрика того дня — 400), `POST /schedule/copy-day` (кнопка «📋 На тиждень»: ТОЧНА копія людей джерельного дня в ті самі зміни вибраних днів або до кінця тижня; `mode=preview` — класифікація ok / без диспозиційності / відпросився / пропуск (busy/скасована клітинка), `mode=apply` + `force` — вставка з копією разового часу зміни й `hoursOverride`; веб шле force на всіх попереджених — диспозиційність інформаційна, не фільтр; під інтеграційними тестами), `POST /schedule/clear` (очистка графіку фабрики на тижні: видаляє лише зміни, що ще не почались за Варшавою, з урахуванням разових змін; минулі й призначення водіїв не чіпає), `PATCH/DELETE /schedule/entry/:id`, `PATCH /schedule/entry/:id/status`, `PUT /schedule/driver-assignments(/by-driver)`, `POST /schedule/driver-assignments/copy-week`, `POST /schedule/notify(-workers|-driver|-drivers)`, `POST /schedule/shift-cancel|shift-restore` (скасування клітинки день+зміна: знімає призначення водіїв, скидає absent, опційні сповіщення працівникам/водіям; entries лишаються scheduled → поза reliability; бот/пуші/pickup-прогалини пропускають скасовані клітинки)

**Облік/відсутності:** `GET /hours` (рядки по парі працівник+фабрика; з cap `svodni` додатково: `unlegalized` на рядку — без форми легалізації і не студент, або oczekuje → червона підсвітка, дзеркало бейджа «?» сводної;
