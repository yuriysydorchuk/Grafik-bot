## Записи

### 2026-07-30 — KSeF не позначав оплачені фактури (прогалина банківських даних)

- **Час / тривалість:** ~01.07–30.07 (весь липень до деплою bank-api), даунтайму не було.
- **Виявлено:** користувач (owner) — оплачені клієнтами фактури висіли «не оплачена».
- **Вплив:** лише статуси оплат sale-фактур у /ksef (P&L не зачеплений — дохід іде за датою виставлення).
- **Проблема (симптоми):** матчинг оплат справний, але в `bank_transactions` на проді не було
  липневих вхідних переказів: MT940-витяги викладаються раз на місяць (липневих ще нема),
  а Enable Banking cron-синк доїхав на прод лише 30.07.
- **Причина (root cause):** розрив «консент авторизовано 28.07 → код синку задеплоєно 30.07».
  Повну історію банк віддає лише свіжому консенту (одразу після SCA); фоновий запит 30.07
  побачив тільки ~2 останні тижні, і частину — фрагментарно. Період 01–26.07 у прод так і не потрапив.
- **Рішення:** разовий бекфіл — експорт 1104 api-транзакцій з локальної БД (там консент
  синкався одразу після авторизації), заливка на прод `ON CONFLICT (dedup_hash) DO NOTHING`
  + прогін sale-пассів `matchKsefPayments` через psql. Результат: 16 оплачених липневих
  фактур, 1:1 з локальною базою.
- **Як уникнути повторення:** новий консент Enable Banking синкати одразу після авторизації
  (кнопка на /bank або `POST /bank-api/sync`), не чекати крону; якщо прогалина вже є —
  бекфіл з БД, де історія була підтягнута вчасно (дедуп-хеші детерміновані, дублікатів не буде;
  липневий MT940 при появі сам замінить api-рядки).

### 2026-06-19 — Перше розгортання на VPS (довідково, не аварія)
- **Вплив:** немає (первинний деплой).
- **Що було:** розгортання з нуля на свіжому Ubuntu 24.04; по дорозі трапилось кілька речей,
  корисних на майбутнє:
  - **`deploy/schema.sql` застарілий** → залили свіжий `pg_dump --schema-only`. Запобіжник:
    перегенерувати й закомітити дамп (TODO в [DATABASE.md](DATABASE.md)).
  - **PG17→PG16 несумісність:** дамп містив `SET transaction_timeout` (нема в PG16) → прибрали рядок.
  - **`pnpm install` виходив з кодом 1** через `ERR_PNPM_IGNORED_BUILDS` (esbuild) → `build.sh`
    навчили толерувати саме цей випадок (esbuild-бінарник іде через `@esbuild/linux-x64`).
  - **Бот стартував з `404 getMe`**, поки `TELEGRAM_BOT_TOKEN` був плейсхолдером → після вписання
    реального токена пішов polling.
  - **SSH throttle:** після багатьох швидких парольних входів сервер обривав з'єднання →
    перейшли на вхід по SSH-ключу.
