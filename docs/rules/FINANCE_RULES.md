# Фінансові правила (обовʼязкові)

Доменні правила фінансового блоку. **Прочитай перед будь-якою зміною** у сводних, зарплатах, авансах, фактурах (/cost-invoices, KSeF), банку/касі чи P&L — тут інваріанти, порушення яких уже були інцидентами. Винесено з `CLAUDE.md` (28.08.2026); нові фінансові правила додавай сюди, а не в CLAUDE.md.

Маршрути фінансових роутерів — `docs/API_ROUTES.md`; продакшн — `docs/infrastructure/`.

---

- **Архів фактур на Google Drive** (`services/invoiceArchive.ts`): гілки `Faktury kosztowe` / `Faktury sprzedażowe` → рік → `M<міс>.<рр>` → фірма; **імʼя файла = «номер фактури + контрагент»** (`archiveFileName`; закупівлі/скани — постачальник, продажі — покупець), **на Диску лише PDF** (рішення 26.08.2026; legacy-XML перших заливів прибрав разовий `upgradeArchiveNamesV2`, guard у settings). PDF для KSeF — візуалізація з XML (`services/ksefPdf.ts`, за зразком стандартних візуалізацій KSeF: шапка/сторони/позиції/VAT/оплата/QR верифікації; шрифти DejaVu в `assets/fonts/`); сам XML лишається локально в `uploads/ksef-xml/` (термін оплати, хеш QR, регенерація). Скани/ручні — PDF (фото загортається через `imagePdf.ts`); ручна фактура на сайті **не зберігається без файла** (UI-вимога). KSeF API PDF **не віддає** — тільки XML; візуалізацію не «спрощувати» до сирих полів. Рядок без файла на Drive несе `drive_error` і світиться червоним на /cost-invoices — не «лагодити» приховуванням.
- **Журнал змін фактур** (`invoice_audit`, `services/invoiceAudit.ts`): кожен create/patch/file/delete на /cost-invoices і /ksef пише «хто-коли-що» (diff полів old→new, імʼя адміна снапшотом); нова точка мутації фактур МУСИТЬ логувати теж. Веб — модалка «Історія фактури» (іконка 🕘 в рядку).
- **Канон полів-двійників** (сторож — `services/dataDrift.ts`: щоденний cron-алерт + лічильник «Потребує уваги»). Вік «до 26» — рахувати з `workers.birth_date` (`isUnder26`), прапорець `under26` — лише фолбек без дати; студент = чекбокс `is_student` АБО `legal_status='student'` (хелпер `stud26Of` в admin-api). Місто фабрики — `factories.city`, далі історія сводних → регіони «Зарплат» (`factoryCityMap`). Снапшоти в `svodni_rows` (city/rate/is_student) — свідомі, не «виправляти». Новий код НЕ читає прапорці напряму.
- **Фабричні правила konto/готівки сводної — у БД, не в коді.** Таблиця `factory_payout_rules` (версії з датою «діє з»; правило діє на сводну МІСЯЦЯ ЦІЛКОМ, у який потрапляє дата): стеля konto-годин (базова/підвищена від порога/лише для фірми), готівковий бонус зл/год, стажевий бонус (сходинки+мін. години), «Premia завжди готівкою». Резолюція — `services/factoryRules.ts` (`PayoutRules.load()` → `.for(factoryId, label, month)`); двигун (`applyLegalDefaults`, `computeSegmented`, `factoryBonusPerHour`) приймає готовий обʼєкт правила (`LegalCtx.rule`). Колишній хардкод (`legacyPayoutRule` у `services/svodni.ts`: стелі DEZYNFEKCJA/SERWIS PLUS/LST 60/70 і Sushi ES 80, бонуси Agram id=12/13 та LST id=1, Premia-cash Agram) — **лише фолбек** для фабрик без збережених версій (сідити БД не можна — id фабрик різняться локально/прод). Нове фабричне правило = версія з сайту (модалка фабрики: перегляд `svodniSensitive`, запис `viewFinance`, після збереження — превʼю/перерахунок незалочених рядків), НЕ нова константа в коді.
- **Фінанси: рапорти мають пріоритет над явками.** Для повних місяців діапазону години пари працівник+фабрика беруться з `monthly_reports` (пропорційне масштабування графікових порцій), без рапорту — із затверджених явок; mtd-порівняння (частковий місяць) — завжди по явках.
- **Фінансові поля — лише для owner** (ставки, рахунки, `viewFinance`/`canFinance`): і в API (фільтрація відповіді), і в UI. Свідомий виняток — cap `factoryRates` (`canFactoryRates`): відкриває **лише ставки в налаштуваннях фабрики** — оплата працівникам (`rate_brutto/rate_netto/night_addon` + `rate/rate_netto` посад) і фактурні (`invoice_rate` фабрики та посад) — для директора міста; привʼязка клієнта до фінблоку (`client_nip`, `pnl_label`) і решта фінансів — як і раніше тільки `viewFinance`.
- **Фінансовий акруал — «місяць мінус 1»:** фактура/зарплата, виставлена чи виплачена в червні за травневу роботу, належить травню (KSeF `revenueMonthFor`, сводні, звірки ЗП банк=M+1). P&L: дохід нетто, собівартість = повна ЗП (брутто+податки+аванси+хостел); сегменти `main`/`cleaning` не змішувати.
- **Жодного матчингу фінансових записів «по сумі».** Евристичний матчинг фактур↔витягів по сумах був відкинутий власником. Дозволено: точний номер фактури в назві переказу, токени імені (звірка ЗП — строгий прохід, потім fuzzy з авто-підтвердженням лише коли сума сходиться ±2 zł, решта — ручне підтвердження у `payroll_name_matches`).
- **Парсери сводних/KSeF — під тестами** (`services/*.test.ts`): формати таблиць гуляють між містами й місяцями; змінюєш парсер — додай/онови фікстуру. Тест-скрипт використовує `test-hooks.mjs` (безрозширенні імпорти під raw Node) і фейковий `DATABASE_URL`.
