# 💰 Модуль 04: Аутсорсинг, фінанси та P&L (Outsourcing & Finance)

## 1. Двоконтурна система обліку та розрахунку годин

У системі діють два незалежні контури:

```
┌─────────────────────────────────────────────────────────────┐
│ 1. КОНТУР ФАБРИКИ (Дохід від клієнта / Фактура)            │
│ • Години, які офіційно зафіксувала та надіслала фабрика.    │
│ • За цими годинами виставляється рахунок фабриці (клієнту). │
└──────────────────────────────┬──────────────────────────────┘
                               │
                      Порівняння / Дельта
                               │
┌──────────────────────────────▼──────────────────────────────┐
│ 2. КОНТУР ПРАЦІВНИКА (Витрати на ЗП / Зарплата)            │
│ • Затверджені години (реально відпрацьовані людиною).       │
│ • За цими годинами нараховується та виплачується заробітна  │
│   плата працівнику (людина бачить їх у боті як основу ЗП).  │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. Генератор додатку до фактури (`Załącznik`)

Для підтвердження рахунку фабриці система автоматично формує щомісячний документ **`Załącznik`**:

### 2.1. Тарифікація відпрацьованих годин за категоріями:
* `Pracownik Fizyczny` (наприклад, ставка 40.00 zł/год).
* `Lider` (ставка 41.50 zł/год).
* `Brygadzista` (ставка 43.00 zł/год).
* `Repack` (ставка 41.50 zł/год).
* **Фільтр стажування (`Wdrożenie`):** навчальні години новачків не тарифікуються клієнту.

### 2.2. Розрахунок підсумкової суми нетто:
$$\text{Razem} = \text{Сума вартості праці (Suma)} - \text{Договірні штрафи (Kary umowne)} - \text{Одяг (Odzież: } N \times 6\text{ zł}) \pm \text{Коригування (Inne)}$$

## 3. Система штрафів фабрики та зв'язок із працівниками

### 3.1. Договірні штрафи клієнта (`Kary umowne`):
* Штрафи, які фабрика виставляє нашому агентству (наприклад, за порушення регламентів, брак тощо).
* Зменшують суму до виплати від фабрики у `Załącznik`.

### 3.2. Персоналізація та перенесення штрафів на винних осіб:
* Якщо договірний штраф викликаний діями конкретного працівника (або неявкою):
  - Штраф прив'язується до профілю працівника в реєстрі штрафів (`penaltiesTable`).
  - У зведеній відомості (`Svodni`) він автоматично відображається у графі `KARA Z SUSHI` (`karaKlient`) та утримується із заробітної плати працівника.
* **Штрафи за помилки бригадирів:** не виписані години покриваються за рахунок утримання з винного бригадира.

## 4. Діагностична звірка годин з автокомпенсацією зсувів (Reconciliation Engine)

* Для кожного дня місяця обчислюється різниця:
  $$\Delta_i = \text{Години}_{Фабрика}(i) - \text{Години}_{Внутрішні}(i)$$
* **Алгоритм самокомпенсації:** дзеркальні розбіжності між сусідніми днями ($|\Delta_A + \Delta_B| < 0.1$ хв через різницю дати нічної зміни) автоматично виключаються зі звіту критичних помилок.
* **Реєстр виключень (Exceptions):** налаштування індивідуальних періодів виключення перевірки `[WorkerID, FromDate, ToDate]`.

## 5. Ієрархія та пріоритет ставок (Rate Resolution Hierarchy)

1. **Базова ставка посади / становіска (Default Position Rate):**
   - Ставка оплати працівнику + ставка виставлення рахунку фабриці.
2. **Індивідуальна ставка працівника (Worker Custom Rate Override):**
   - Персональна ставка має найвищий пріоритет:
     $$\text{Діюча ставка} = \text{Персональна ставка працівника} \;\;??\;\; \text{Базова ставка посади}$$
3. **Фіксація в інтервалі:**
   - Діюча ставка фіксується в момент виконання роботи і не змінюється при наступних змінах тарифів.
