# HANDOFF: разові зміни + штрафи відсутностей (сесії 30–31.07.2026)

Одноразова записка сесії. Довговічні правила вже перенесені в канонічні доки:
правило «зміни поза shiftCount — легальні» → `CLAUDE.md`; маршрути/схема/ризик —
`PROJECT_MAP.md`. Тут — що саме зроблено, разові кроки і на що дивитись після деплою.

## Що зроблено (6 задач власника + 2 фікси)

1. **Графік не «зникає» при зміні кількості змін фабрики.** Причина була у показі:
   всі поверхні різали зміни по `shiftCount`. Тепер множина змін = «налаштовані ∪
   зміни з реальними записами» скрізь: веб-сітка (`Schedule.tsx`), Замовлення,
   пресмінні/pickup-пуші (`scheduler.ts`), `/live`, `/driver-board`, `pickupGaps.ts`,
   Excel клієнту (`drive.ts`), бот-в'ю водія.
2. **Разова зміна на день** — таблиця `factory_shift_overrides` (фабрика+дата+№+час),
   `POST/DELETE /api/schedule/shift-override`, кнопка «➕ Зміна» на дні графіку.
   Час override пріоритетний над `factories.shifts` (резолвер — `services/shiftOverrides.ts`);
   тривалість пишеться в `schedule_entries.hours_override` (облік/фінанси коректні).
3. **Генерація має режим «Доповнити»** (`POST /schedule/generate {augment:true}`):
   наявні призначення не видаляються, заповнюються лише порожні клітинки.
4. **Бот, диспозиційність:** підказка «не відмітив = вихідний» (intro + під клавіатурою)
   і проміжне підтвердження «Ви впевнені, що хочете взяти вихідний на …?» з
   «✅ Так, зберегти / ✏️ Виправити» — 5 мов (`av.confirmOff/Yes/Edit` у `bot/i18n.ts`).
5. **Excel обліку годин:** модалка вибору стовпчиків (Kod / Imię / Fabryka / raport /
   fabryka / Różnica / Status) + перемикач «лише рядки з помилками»
   (`GET /hours/report-excel?cols=…&errorsOnly=1`, каталог `HOURS_XLSX_COLS` у `drive.ts`).
6. **Доступність:** липкі шапки (назва фабрики під топбаром + рядок днів під нею, md+;
   без внутрішнього скролу таблиці — попередня версія з `max-h` була помилкою).
7. **Відсутності:** «виправдати» пропуск (`schedule_entries.absence_excused` — поза
   кількістю і штрафом), штраф за пропуск (стандарт **300 zł**, `absence_penalty`:
   NULL = стандарт, 0 = анульовано, число = свій розмір; константа
   `DEFAULT_ABSENCE_PENALTY` в `admin-api.ts`), `PATCH /api/absences/:entryId`.
   UI: зведення по працівниках (фабрика, лічильники, сума штрафів, сортування,
   клік → деталі з діями), фільтр «Тільки виправдані».

## На що дивитись після деплою

- Пресмінні пуші: разова зміна шле нагадування з часом override (вікно 106–134 хв до старту).
- `GET /driver-board` і бот водія показують клітинки зміни «3» на фабриці з 2 змінами.
- «Перегенерувати» тепер відкриває вибір «Доповнити / Перегенерувати все» — доповнення
  не чіпає наявне (перевірити на живому тижні перед масовим використанням).
- Відсутності: штраф з'являється лише для затверджених тижнів (absences читає approved-only).
