## #7 — Safari: знімок «висить» до перемикання вкладки
Відомий баг WebKit: `HTMLImageElement.decode()` для SVG-зображення (а знімок modern-screenshot — це SVG з foreignObject) не завершується, поки сторінка не перемалюється; перемикання вкладки дає перемалювання. Headless WebKit (Playwright) цього не відтворює. modern-screenshot 4.7.0 — остання версія, `decode()` чекає без таймауту (`loadMedia` → `await node.decode()`).
**План:** на час знімка обгорнути `HTMLImageElement.prototype.decode` гонкою з таймаутом ~300 мс (картинка вже `load`-нута, малювання в Safari бібліотека й так повторює `drawImageCount` разів), після знімка повернути оригінал. Плюс крихта з тривалістю, щоб наступне зголошення показало, чи допомогло. Перевірка: Chrome/WebKit локально + попросити графікову перевірити в Safari (повністю відтворити можна лише в справжньому Safari: safaridriver потребує ввімкненої «Allow Remote Automation»).

## #12 — посади всередині фабрики, колір, Biuro
Зараз: `positions` — глобальний каталог (назва, колір, KZiS); `factory_positions` — пара фабрика×посада (ставки, обовʼязки, uaStanowisko, KZiS) — тобто «посади фабрики» вже є, але розкидані по трьох місцях (Фабрики → «Розрізняти посади», praca.gov → Фабрики, Налаштування → Посади). У працівника одна посада на всі фабрики (`workers.position_id`); від неї — секція сводної, ставка (ланцюжок rateRules), {%Stanowisko%} в умові, KZiS у powiadomieniu. Колір — `<select>` із сирими ключами Tailwind («slate/amber»), без кружечків (`Settings.tsx`). Знайдено баг: видалення посади, що стоїть на фабриці, — 500 (перевіряються лише працівники). Фабрики «Biuro» на проді нема (офіс як фабрика з `is_office` — рішення 05.09; шаблон «Umowa — BIURO» є, ні до чого не привʼязаний).
**План етапами:** (a) S — вибір кольору кружечками (+ воронки), видалення посади з фабрики — зрозуміла 400 замість 500. (b) M — Налаштування → Посади по фабриці: обрав фабрику → її посади з кольором, ставками (лише owner/factoryRates), KZiS, uaStanowisko, обовʼязками в одному місці; нова посада = каталог + рядок фабрики; глобальний каталог лишається довідником назв. (c) L, фінансово критично — різна посада людини на різних фабриках: таблиця `worker_factory_positions` + резолвер з фолбеком на профіль, заміна в сводній, обліку, ставках, умовах, powiadomieniu, графіку; `mergeWorkers`; тести сводної. (d) S — «Biuro» як офісна фабрика (`is_office`, кілька фірм), офісні посади через (b), шаблон BIURO привʼязати; компанію «Biuro» не створювати — офісних наймають ES/ESO/Klinex (уточнити у власника).

## #13 — «ZUA зголошення» у фільтрі задач
Відповідь: у джерело «ZUS ZUA (новий)» (`auto:hire_zus`) потрапляє кожен, у кого умову підписали обидві сторони, студенти теж — але їхня задача «студент до 26, лише Gratyfikant» (до ZUS не зголошувати, закривається вручну). Виреєстрування — окреме джерело «ZUS ZWUA», документи звільнення — «документ звільнення». Фільтр вибирає одне джерело.
**План (S):** зрозумілі підписи джерел («ZUS: зголошення (ZUA / Gratyfikant)», «ZUS: виреєстрування (ZWUA)», «Звільнення: документи»), групування в `<optgroup>`, груповий пункт «ZUS: зголошення + виреєстрування» (бекенд `source` через кому → `inArray`), запамʼятовувати вибір. **Рішення власника:** студенту до 26 без ZUA не створювати ZWUA-задачу (або закривати авто); чи має ZZA закривати задачу зголошення.

## #14 — копіювання даних у профілі
Зараз `InlineText` (WorkerDetail) відкриває input одним кліком (PESEL, друге ім'я, Telegram, телефон, Gratyfikant); ім'я в шапці й дата народження клікаються навіть без права редагування. Дані анкети — лише у формі-модалці.
**План (M):** (а) клік — копіює (тост «Скопійовано»), олівець / подвійний клік — редагує (на тач-екранах олівець видимий завжди); ім'я й дату народження закрити перевіркою прав; спільний `lib/clipboard.ts`. (б) картка «Дані для копіювання» (лише з `workerDocs`): ПІБ, PESEL, дата народження, паспорт + дійсний до, громадянство, адреси, рахунок (`fmtIban`), телефон, email, NIP, urząd, NFZ — кожне з кнопкою копіювання + «Скопіювати все».
