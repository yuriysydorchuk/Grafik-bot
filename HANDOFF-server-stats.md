# HANDOFF — тижневий дайджест здоровʼя сервера (10.08.2026)

Сесійна записка. Довговічне вже перенесено в канон: cron-рядки — `PROJECT_MAP.md → Cron / jobs`,
опис і пороги — `docs/infrastructure/ALERTING.md → Тижневий дайджест сервера`.

## Що зроблено

Власник отримує в бот щотижневу статистику сервера (запит: «скільки місця зайнято/залишилось,
наскільки завантажений сервер, чи не треба покращувати»).

- **Новий сервіс** `artifacts/api-server/src/services/serverStats.ts`:
  - семпл кожні 15 хв: `os.loadavg()` + `MemAvailable` з `/proc/meminfo` (не `os.freemem` —
    на Linux той не бачить page cache); ролінг-вікно 7 днів у `settings` (ключ
    `server_stats_samples`, ~672 семпли) — без зміни схеми БД, переживає рестарти pm2;
  - дайджест пн 08:00 Warsaw головному адміну (`admins.is_main`): диск (`fs.statfs`,
    use% як у df) + розмір БД (`pg_database_size`) + `uploads/`, CPU/RAM за тиждень
    (сер./пік), аптайм сервера й процесу, вердикт ✅/⚠️/🔴 з причинами
    (пороги: диск 80/90%, load на ядро 50/70%, RAM 80/90%);
  - диск ≥90% → негайний `sendAlert` уже з семплінгу, дедуп раз на день
    (працює лише при `ALERTS_ENABLED=true` на проді; сам дайджест від цього не залежить).
- **Крон** — два завдання в `services/scheduler.ts` (`*/15` семпл, `0 8 * * 1` звіт),
  обидва з лінивим імпортом і catch-ами, зупиняються в `stopScheduler`.
- **Тести** — `serverStats.test.ts`: 9 юнітів на чисті функції (trim/агрегація/вердикт/формати).
  `sendAlert`/`bot` у сервісі імпортуються ліниво — модуль імпортується без TELEGRAM_BOT_TOKEN.
- **Смоук** — `artifacts/api-server/scratch-server-stats.mjs` (untracked): семпл у локальну БД
  і друк звіту без відправки. На macOS RAM показує ~99% — артефакт фолбека `os.freemem()`,
  на Linux-проді цифри чесні.

## Стан / що далі

- Код на проді (коміт `3849b23`), міграцій не було.
- Перший дайджест — найближчий понеділок 08:00; повне 7-денне вікно семплів набереться
  через тиждень після деплою (до того — по наявних семплах).
- Разовий алерт про диск ≥90% потребує `ALERTS_ENABLED=true` у прод `.env` — перевірити,
  чи ввімкнено (див. `docs/infrastructure/ALERTING.md`).
