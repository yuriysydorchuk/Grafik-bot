# HANDOFF: Фабричні правила konto/готівки сводної (22.08.2026)

Одноразова записка сесії. Довговічні правила вже перенесені: CLAUDE.md («Фабричні
правила konto/готівки — у БД») + PROJECT_MAP.md (роути в розділі Сводні).

## Що зроблено

Правила розкладу konto/готівка по фабриках винесені з хардкоду в БД і редагуються
з сайту, версіями з датою «діє з» (**місяць цілком**: сводна місяця, в який
потрапляє дата, вже за новим правилом — рішення Yuriy 22.08).

- **Схема:** нова таблиця `factory_payout_rules`
  (міграція `deploy/migrations/2026-08-22-factory-payout-rules.sql`): стеля
  konto-годин (базова / підвищена від порога відпрацьованих / лише для фірми),
  готівковий бонус зл/год, стажевий бонус (сходинки {days, add} + мін. год/міс),
  `premia_cash`, note, created_by.
- **Двигун** (`services/svodni.ts`): інтерфейс `PayoutRule`; `applyLegalDefaults`
  (`LegalCtx.rule`), `computeSegmented` (`parent.rule`), `factoryBonusPerHour(w, rule, …)`,
  `declaredCapOf`, `hasCashBonus`. Колишній хардкод зібраний у `legacyPayoutRule`
  — **лише фолбек** для фабрик без версій (сід у БД свідомо НЕ робився: id фабрик
  різняться локально/прод). Константи AGRAM_FACTORY_IDS/LST_FACTORY_ID/
  CASH_BONUS_FACTORY_IDS живуть тільки в legacy-фолбеку і тестах.
- **Резолюція:** `services/factoryRules.ts` — `PayoutRules.load()` →
  `.for(factoryId, label, month)` (найсвіжіша версія з effective_from ≤ кінець
  місяця, інакше legacy).
- **Перешиті всі споживачі:** from-hours, PATCH рядка, apply-rates, «Додати
  людину», unsplit, сегментний двигун (`recomputeSegmentedParent`), freeze
  under-26 при локу, profile-impact/apply, транспорт/одяг/бадання/кари-переноси
  (`writeKaraCell` і компанія), синк із Google (`svodniSync.ts`), прапорці
  бонус-галочок у профілі працівника (`admin-api.ts` — тепер від чинного правила
  фабрики на поточний місяць).
- **API** (`routes/svodni.ts`): `GET /svodni/factory-rules?factoryId`
  (svodniSensitive), `POST/PATCH/DELETE /svodni/factory-rules(/:id)` (viewFinance),
  `POST /svodni/factory-rules/impact|recompute` (viewFinance) — dry-run/перерахунок
  незалочених рядків фабрики від місяця: бонус **дельтою** до ставки рядка (ручні
  правки ставок не скидаються), konto/готівка ланцюжком ручної правки, сегментовані
  — через сегментний двигун; залочені пропускаються списком.
- **Веб** (`pages/Factories.tsx`): блок «Правила сводної (konto/готівка)» у модалці
  фабрики (перегляд svodniSensitive, редагування viewFinance): чинне правило
  (бейдж «спадкове з коду» до першої версії), історія версій (👁 вплив / ✏️ / 🗑),
  форма версії з «Діє з». Після збереження/видалення — модалка «На що вплине
  правило» показується **завжди** (нульовий вплив — явним текстом, не тостом;
  допрацювання за фідбеком Yuriy), підсумок по місяцях, кнопка «Перерахувати
  незалочені (N)». i18n uk→en повний.
- **Тести:** нові юніти двигуна (кастомне правило: сходинки/стелі/premia-cash) +
  `routes/factory-payout-rules.integration.test.ts` (гейти, місячна резолюція,
  recompute зі стелею і бонус-дельтою, повага локів). Прогін: 432/432.

## Відкрите / нюанси

- Рядки сводних без `factory_id` (старі непривʼязані вкладки) recompute свідомо
  не чіпає; синк/from-hours для них працює як раніше (legacy по label).
- Eurocash-пороги (`EUROCASH_FACTORY_IDS` = 9/8) лишаються хардкодом — рішення
  Yuriy 22.08 («це не робимо»).
- `staleLocks`/ревʼю при розлоку відстежують лише зміни профілів (worker_changes);
  зміна фабричного правила під локом у ревʼю розлоку НЕ зʼявиться — але impact/👁
  на версії показує залочені рядки списком «не зміняться».
