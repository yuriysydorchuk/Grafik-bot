# HANDOFF: Інтеграція з Gratyfikant nexo PRO (14–24.08.2026)

Разова записка сесій про побудову мосту «сводні → Gratyfikant nexo PRO» (кадрова
система księgowej, InsERT). Довговічні правила — у `PROJECT_MAP.md` (блок Сводні
та роут `/gratyfikant`); тут — контекст, рішення і відкриті хвости.

## Що працює (задеплоєно)

- **Налаштування → Gratyfikant** (cap `svodniSensitive`): імпорт вивантажень з nexo.
  Тип файлу визначається по заголовках: список умов (`Nr umowy`) або картотека
  (`PESEL`). Кожна зміна показується окремим рядком (dry-run) і **схвалюється
  галочкою**; нечіткі матчі за замовчуванням зняті. Пише `workers.pesel` і
  `workers.gratyfikant_name` (лише порожні), знімок умов — у `gratyfikant_umowy`
  (імпорт заміняє рядки своєї фірми).
- **/svodni → кнопка Gratyfikant**: ліста до виплат — фірма (одна!) → скоуп
  (всі фабрики / місто / вибрані) → превʼю людей з сумами і попередженнями
  (без PESEL / нема умови / умова скінчилась / умова в іншій фірмі) → галочки →
  файл **без заголовка**: `Імʼя (нексо) | PESEL | Дата виплати | Сума` (księg.
  brutto; критерій «іде щось на конто»; дата — 25-те наступного місяця).
- Матчер імен (фолд діакритиків → точний → перестановка/підмножина → обережний
  fuzzy) — `services/gratyfikantImport.ts` під тестами; генератор —
  `services/gratyfikantExport.ts` під тестами.

## Як цим користуватись щомісяця

1. Раз на місяць-два: вивантажити з nexo списки умов (3 підмiоти) і картотеки з
   PESEL → імпортнути в Налаштуваннях (превʼю → схвалити).
2. Після затвердження сводної місяця: /svodni → Gratyfikant → фірма → скоуп →
   перевірити попередження → скачати лісту → зберегти на машині księgowej →
   у nexo — Nalicz wynagrodzenia (складник читає файл функцією `WartoscZArkusza`).

## Ключові знання про nexo (кров'ю здобуті)

- Вбудований імпорт «Naliczenia i potrącenia» (Laboratorium) у їхній базі
  **зламаний**: навіть ручне додавання каже «pracownik nie posiada umowy» для
  всіх (версія 61.0.3, ліцензія ок). Не використовуємо; в InsERT не репортили.
- Робочий механізм — **składnik definiowalny + `WartoscZArkusza(шлях, аркуш,
  колонка-ідентифікатор, 0, 0, колонка-суми, 0, "P"|"NI")`**: поштучний rachunek
  з умови рахує; **масовий креатор рахує тільки в режимі «на підставі системи»**
  (той, що «робить всім»), ручний режим з вибором умов означення НЕ виконує —
  туди суми вставляються `Ctrl+V` (це офіційний прийом). CSV-файли їхній парсер
  відкидає («niewłaściwa liczba kolumn») незалежно від розділювача — лише xlsx.
- Складники видно з definicji listy płac; значення складника НА умові перекриває
  означення (нулі на умовах = нулі в масовому наліченні). Вбудований дефолтний
  складник «Rachunki - kwota rachunku» видалити з definicji не можна.
- Лісти рахунків фільтрують умови по місяцю лісти: ліста за пізній місяць
  «губить» людей, чиї умови скінчились (місяць лісти = місяць ПРАЦІ, дату
  виплати міняють масово в креаторі).
- Виплата: у серпні (25-го) платимо за липень → дата у файлі = 25-те M+1.
